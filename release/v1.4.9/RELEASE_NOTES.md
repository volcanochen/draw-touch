# v1.4.9 发布说明

发布日期：2026-10-30

> 这是 v1.4.8 之后的**设置页重构版本**：设置项按 8 个类别重新归置，
> **横屏排成两列**充分利用横向空间，所有分类**统一卡片结构**。
> 双端版本号统一为 **1.4.9**（PC 端托盘第一行显示「版本 + 构建于」）。

## 🎯 本轮主打：设置页分类重整 + 横屏两列

### 之前的问题

设置页是一个长长的 `ScrollView`，几十个控件按加入顺序从上往下堆：

- 「连接」和「模式与映射」和「触觉反馈」混在一起，找一个参数要上下翻很久
- 标签和数值挤在同一个 `TextView` 里（`"滚轮动量（1.0 = 抬手滚 3 秒停） 3.0"`），
  **标签一换行，数值就被顶到第二行**，跟上一行的卡片边贴在一起
- 横屏下那条长页面**完全没利用横向空间**，一行还是那么长，要滚很久

### 现在的结构：8 个分类，统一卡片骨架

| # | 分类 | 内容 |
|---|---|---|
| 1 | **连接** | PC 地址 / 端口、连接、mDNS 发现、网段扫描 |
| 2 | **模式与映射** | 比例映射、手指的作用、转发悬停移动、压感增益 |
| 3 | **指针与滚动** | 光标速度、滚动比例、拖框死区、指针平滑档位、滚动模式、滚轮动量、触摸板颜色 |
| 4 | **按压识别** | 总开关 + 触发阈值 / 确认帧数 / 松开余量 / 压力阈值 + 实时状态查看器 |
| 5 | **手势绑定** | 双指到四指的点击与滑动，各自绑定的动作 |
| 6 | **触觉反馈** | 震动开关、震动强度、覆盖系统震动强度限制 |
| 7 | **显示与截图** | 截图范围、存到电脑 / 手机相册、手指轨迹 |
| 8 | **关于** | 版本信息、检查更新、项目主页 |

**每一个分类都是同一个骨架**，扫一眼就知道每一块是干什么的：

```
┌─────────────────────────────────┐
│ 分类名（蓝色标题）               │  ← 14f，#7FD1FF
│ 一句说明（灰色小字，可选）       │  ← 11f，#9E9E9E
│ ─────────────────────────────── │
│ 这一类的各项控件                 │  ← 内容区
└─────────────────────────────────┘
```

### 横屏：两列并排，各自独立滚动

- **竖屏**：单列，一列到底
- **横屏**：**两列并排**，横向空间充分利用
  - 左列：连接 / 指针与滚动 / 手势绑定 / 显示与截图
  - 右列：模式与映射 / 按压识别 / 触觉反馈 / 关于
- 两列**各自独立滚动** —— 短的一列滚到底就停，不会被另一列拖着走
  （如果用一张 ScrollView 装两列，就得为了对齐高度留一大片空白）

### 顺带修掉的排版问题

1. **数值独立成列**：`[−] 标签 ...... 数值 [+]`
   数值右对齐、蓝色，标签换行时数值**不再被挤到第二行**
2. **标题栏压成一行**：`设置  v1.4.9 (code 25) · 构建于 …  [完成]`
   原来「设置」和版本小字是竖排两行，横屏时白白吃掉 1/4 的屏幕高度
3. **版本号单行 + 尾部省略**：窄屏时不再折行把标题栏撑成两行；
   完整信息（版本号 + code + 构建时间）移到「关于」分类里，随时可查
4. **正文底部避开系统导航条**：最后一张卡片不会被手势条压住
5. **长标签精简**：`滚轮动量(抬手滚3秒)` → `滚轮动量`（说明挪到分类说明里）、
   `触发阈值(面积涨幅)` → `触发阈值`、`压力通道阈值` → `压力阈值`、
   `滚动/拖框死区 dp` → `拖框死区 dp`

### 🐛 修掉一个转屏不重建的 Bug

设置页开着时转屏，**布局不重建**（横屏两列会被硬塞进竖屏，变成两条被压扁的窄列）。

根因：`onConfigurationChanged` 回调里读 `resources.configuration`，
拿到的还是**旧方向**。修法是转屏时把 `newConfig.orientation` 显式传进重建函数，
不再依赖 `resources`。修后竖↔横实时切换正常（设置页不用关再开）。

## 🧭 顺带调整：「跟随系统」真的跟随系统

「屏幕方向」循环按钮的三档里，第一档「跟随系统」原来用的是
`SCREEN_ORIENTATION_FULL_SENSOR` —— 名字叫跟随系统，**实际是永远跟陀螺仪**，
无视系统的自动旋转开关。

后果很实际：手机平放在桌上用触摸板，陀螺仪随手一碰它就自己横过来。

改成 `FULL_USER`：**听系统的自动旋转开关**。系统开着自动旋转就跟着转，
用户锁了方向就保持锁定 —— 名副其实。

> 「横屏 / 竖屏」两档不变，仍然是陀螺仪双向自动翻转（拿着手机转个手就翻面）。

## 🐛 修掉一个发布包根本跑不起来的 Bug（v1.4.8 的 zip 是坏的）

**v1.4.8 的 PC 端 zip 下载解压后双击 exe 是跑不起来的**，报：

```
The application to execute does not exist: '...\DrawTouchHost.dll'
```

根因：上一轮为了「把 exe 从 153MB 缩到 9.6MB」把打包源从 `dotnet publish` 换成了
`dotnet build` 的产物 —— 但这两个产物根本不是一回事：

| 产物 | 大小 | 是什么 | 能不能单独拷走跑 |
|---|---|---|---|
| `dotnet build` 的 exe | 9.6 MB | **apphost 壳**，靠旁边的 60 多个 dll + .NET 运行时启动 | ❌ 不能，缺 dll 就报错 |
| `dotnet publish` 的 exe | 162 MB | **自包含单文件**，运行时 + WPF 原生库全内嵌 | ✅ 能，零依赖 |

zip 里只带了 7 个文件（照抄 v1.3.1 的结构），而 build 产物需要的是几十个 dll
→ 少一个都起不来。**这是 v1.4.8 的真实缺陷，不是理论风险。**

而且当时的校验脚本是「在 exe 里明文搜版本号」——单文件发布会把程序集压缩进 exe，
**根本搜不到**（v1.3.1 的包也搜不到），所以那个检查**一直是假的**，缺陷没被拦住。

v1.4.9 的修法：

1. csproj 固化 `IncludeNativeLibrariesForSelfExtract=true`（原生库也进单文件）
2. `make_release.py` 改为**自动跑 `dotnet publish`** 再打包，不再手挑文件
3. zip 结构改为 **2 个文件**：`DrawTouchHost.exe`（自包含单文件）+ `appsettings.json`
4. 新增 host 的 `--version` 参数（提权逻辑之前，不会弹 UAC、不占端口），
   校验脚本改成**解压到空目录 → 实跑 `exe --version` → 必须输出正确版本号**
5. 打包脚本在打 zip **之前**也自检一次 exe 能否独立报版本

现在 PC 端 zip **65.5 MB**（和 v1.3.1 的 65.7 MB 基本一致），
解压即用，不需要装 .NET 运行时。

> 换句话说：**v1.4.8 的 PC 端包请不要用**，用这个 v1.4.9 的。
> 手机端 APK 不受影响（v1.4.8 的 APK 是好的）。
